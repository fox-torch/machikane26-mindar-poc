# MindAR.js 実機検証計画

## 目的
MindAR.js が本企画の画像認識基盤として使えるかを、認識可否だけでなく再認識・誤認・姿勢値の安定性まで含めて判断する。

## 先に確認するPoC
1. 参考4ターゲットを個別に識別できること。
2. target 0〜2の認識で BLUE / RED / GREEN の currentFilter が保持されること。
3. target 3で相対xyz・回転・target-width単位の距離が更新されること。
4. CSVに found / lost / filter_changed / 500msサンプルが残ること。

## 1マーカーごとの試験
- 正面距離: 20 / 40 / 60 / 100 cm
- 水平角度: 0 / 30 / 45 deg
- 照明: 通常 / 暗所 / 逆光
- 遮蔽: 0 / 約25%
- 各条件3回

## 記録する値
- 初回認識までの体感時間
- found / lost 回数
- 連続ロック時間
- 誤ったtarget indexの有無
- 相対xyz / 回転の揺れ
- 実測距離と概算distance(mm)の差
## 本番画像が揃った後の負荷試験
設計上は床観測孔8地点、Filter複数、窓ポスター4チーム分が必要。最終 `.mind` 候補を作り、ターゲット数増加時の初期ロード時間・認識速度・誤認を再測定する。

## 端末比較
最低でも以下を同じマーカー・同じ条件で比較する。
- iPhone Safari
- Android Chrome

端末名、OS、ブラウザ版もCSVとは別に記録する。

## 判定上の注意
- 参考画像で良好でも、本番画像の特徴点が弱ければ結果は再現しない。
- Filterは色そのものを画像分類するのではなく、カード全体を画像ターゲットとして識別するPoC。
- 実距離値はMindARの正規化座標からの概算なので、ゲーム判定に距離を使う場合は別途校正が必要。
- 窓ポスターは本番環境の逆光で必ず再試験する。

## 次工程
1. 本番Filterカード案を3種以上作成して `.mind` 化する。
2. 床観測孔候補を8種作成し、離れた距離・斜め角度で比較する。
3. ポスター候補を本番窓位置で検証する。
4. Web班と `FILTER_CHANGED` 送信形式を確定後、PoCにWebSocket送信を追加する。
